# Sesión 3 — UD1. Amenazas, vulnerabilidades y riesgos

## 1. Punto de partida

Cuando hablamos de seguridad informática hay cuatro preguntas que debemos hacernos:

1. ¿Qué puede causarnos daño?
2. ¿Qué debilidad puede aprovechar?
3. ¿Qué puede ocurrir si se aprovecha?
4. ¿Qué podemos hacer para evitarlo o reducir sus consecuencias?

De aquí salen cuatro conceptos fundamentales:

```text
AMENAZA → VULNERABILIDAD → RIESGO → ATAQUE
```

---

## 2. Amenaza

### ¿Qué es una amenaza?

Una **amenaza** es cualquier elemento o situación que puede causar un daño.

Por ejemplo:

- Un atacante.
- Un malware.
- Un virus.
- Un incendio.
- Un fallo eléctrico.
- Un usuario que comete un error.
- Un ransomware.

La amenaza **no significa necesariamente que el daño haya ocurrido**.

> **Amenaza = aquello que puede causar el daño.**

### Ejemplo para clase

Imaginemos un ordenador conectado a Internet.

```text
ORDENADOR
    │
    └── Internet
          │
          └── Atacante
```

El atacante es una posible **amenaza**.

Pero todavía no existe necesariamente un ataque.

---

## 3. Vulnerabilidad

### ¿Qué es una vulnerabilidad?

Una **vulnerabilidad** es una debilidad que puede ser aprovechada por una amenaza.

Ejemplos:

- Sistema operativo sin actualizar.
- Software vulnerable.
- Contraseña débil.
- Servicio innecesario expuesto.
- Configuración incorrecta.
- Puerta abierta.
- Falta de copias de seguridad.

> **Vulnerabilidad = debilidad que puede aprovecharse.**

---

## 4. Ejemplo práctico: buscar servicios en nuestro propio equipo

Una forma sencilla de entender el concepto es observar qué servicios están escuchando en nuestro ordenador.

### PowerShell

```powershell
Get-NetTCPConnection -State Listen |
    Select-Object LocalAddress,LocalPort,OwningProcess
```

Podemos obtener algo parecido a:

```text
LocalAddress LocalPort OwningProcess
------------ --------- -------------
0.0.0.0      135      1234
0.0.0.0      445      4567
127.0.0.1    8000     9876
```

La pregunta para los alumnos es:

> ¿Tener un puerto abierto significa automáticamente que existe una vulnerabilidad?

**No.**

Un puerto abierto simplemente indica que existe un servicio escuchando.

Tenemos que conocer:

- Qué servicio es.
- Para qué sirve.
- Si debe estar accesible.
- Cómo está configurado.
- Si está actualizado.
- Si requiere autenticación.
- Desde dónde puede accederse.

## 6. Riesgo

### ¿Qué es el riesgo?

El **riesgo** representa la posibilidad de que una amenaza aproveche una vulnerabilidad y produzca un daño.

Podemos explicarlo de forma sencilla:

```text
AMENAZA
   ↓
aprovecha una
   ↓
VULNERABILIDAD
   ↓
puede producir
   ↓
DAÑO
   ↓
RIESGO
```

Una forma habitual de representarlo es:

```text
RIESGO ≈ PROBABILIDAD × IMPACTO
```

### Ejemplo

Un ordenador tiene un servicio innecesario expuesto.

```text
Amenaza:
Atacante

Vulnerabilidad:
Servicio innecesario expuesto

Impacto:
Acceso no autorizado

Riesgo:
Posibilidad de que el servicio sea utilizado
para comprometer el sistema
```

---

## 7. Ataque

### ¿Qué es un ataque?

Un **ataque** se produce cuando una amenaza se materializa aprovechando una vulnerabilidad.

Por ejemplo:

```text
Amenaza:
Atacante

        ↓

Vulnerabilidad:
Contraseña débil

        ↓

Ataque:
Intento de acceso

        ↓

Consecuencia:
Acceso no autorizado
```

Por tanto:

> **Amenaza ≠ ataque**

Una amenaza puede existir sin que se haya producido un ataque.

---

## 8. No confundir los conceptos

| Concepto | Significado |
|---|---|
| **Amenaza** | Puede causar daño |
| **Vulnerabilidad** | Debilidad que puede aprovecharse |
| **Riesgo** | Posibilidad de que se produzca un daño |
| **Ataque** | La amenaza se materializa aprovechando una vulnerabilidad |

---

## 9. Ejemplo completo para explicar en clase

Supongamos que tenemos un servidor SSH.

```text
Servidor Linux
      │
      └── SSH
           │
           └── Puerto 22
```

Tenemos:

### Amenaza

Un atacante intenta acceder al servidor.

### Vulnerabilidad

El servidor permite autenticación mediante una contraseña débil.

### Riesgo

Existe la posibilidad de que alguien consiga acceder al servidor.

### Ataque

El atacante realiza intentos de autenticación.

### Daño

Si consigue acceder:

- Puede consultar información.
- Puede modificar archivos.
- Puede ejecutar comandos con los permisos obtenidos.
- Puede comprometer otros recursos.

# 10. Demostración segura en Bash

Podemos crear en nuestro propio equipo un pequeño ejemplo.

## Crear un archivo

```bash
echo "Información de ejemplo" > datos.txt
```

Comprobamos sus permisos:

```bash
ls -l datos.txt
```

Podemos modificar los permisos para mostrar una configuración demasiado permisiva:

```bash
chmod 777 datos.txt
```

Volvemos a comprobar:

```bash
ls -l datos.txt
```

Ahora podemos explicar:

```text
Amenaza:
Usuario o proceso no autorizado

Vulnerabilidad:
Permisos excesivamente permisivos

Riesgo:
Posibilidad de modificación o lectura no autorizada

Daño:
Alteración de la información
```

Después podemos corregirlo:

```bash
chmod 644 datos.txt
```

## 11. Demostración en PowerShell

En Windows podemos observar los permisos de un archivo.

Crear un archivo:

```powershell
"Información de ejemplo" | Set-Content datos.txt
```

Consultar los permisos:

```powershell
Get-Acl .\datos.txt | Format-List
```

Podemos explicar que los permisos son una parte importante de la seguridad.

La pregunta para clase es:

> ¿Qué ocurre si un usuario tiene más permisos de los que necesita?

Esto nos lleva al principio de:

**mínimo privilegio**.

## 12. Tipos de amenazas

Podemos dividir las amenazas en tres grandes grupos.

### 12.1. Amenazas humanas

#### Intencionadas

Personas que buscan provocar un daño.

Ejemplos:

- Atacantes.
- Ciberdelincuentes.
- Usuarios maliciosos.

#### Accidentales

Personas que provocan un incidente sin intención.

Ejemplos:

- Borrar un archivo.
- Equivocarse de destinatario.
- Configurar incorrectamente un servidor.
- Introducir información incorrecta.

---

## 13. Amenazas lógicas o de software

Son amenazas relacionadas con software o sistemas informáticos.

Ejemplos:

- Malware.
- Virus.
- Ransomware.
- Troyanos.
- Vulnerabilidades de software.
- Ataques contra aplicaciones.

---

## 14. Amenazas físicas o ambientales

No todos los problemas de seguridad son ataques informáticos.

Ejemplos:

- Incendio.
- Inundación.
- Robo.
- Corte eléctrico.
- Avería.
- Sobrecalentamiento.
- Desastre natural.

> **La seguridad informática también depende de la seguridad física.**

---

## 15. Seguridad activa

La **seguridad activa** intenta prevenir, detectar o detener los incidentes.

Podemos asociarla con:

```text
EVITAR
DETECTAR
DETENER
```

Ejemplos:

- Cortafuegos.
- Antimalware.
- Contraseñas.
- MFA.
- Actualizaciones.
- Sistemas IDS/IPS.
- Control de acceso.

---

## 16. Seguridad pasiva

La **seguridad pasiva** intenta reducir las consecuencias de un incidente y facilitar la recuperación.

Ejemplos:

- Copias de seguridad.
- Redundancia.
- SAI.
- Sistemas RAID.
- Sistemas de recuperación.
- Replicación.

Idea sencilla:

```text
Seguridad activa
       ↓
Intentar evitar el problema


Seguridad pasiva
       ↓
Reducir las consecuencias
si el problema ocurre
```

---

## 17. Ejemplo práctico: una copia de seguridad

Creamos un archivo:

```bash
echo "Documento importante" > documento.txt
```

Creamos una copia:

```bash
cp documento.txt documento-backup.txt
```

Ahora eliminamos el original:

```bash
rm documento.txt
```

Comprobamos:

```bash
ls
```

El archivo original ha desaparecido, pero tenemos una copia.

```text
Incidente
   ↓
Se pierde el archivo
   ↓
Existe una copia
   ↓
Podemos recuperarlo
```

La copia de seguridad es una **medida de seguridad pasiva**.

---

## 18. Seguridad activa + seguridad pasiva

En un sistema real necesitamos ambas.

```text
                SEGURIDAD
                    │
          ┌─────────┴─────────┐
          │                   │
       ACTIVA              PASIVA
          │                   │
     Previene              Recupera
     Detecta               Reduce daño
     Detiene               Mantiene copias
          │                   │
      Firewall              Backup
      MFA                   SAI
      Antivirus             Redundancia
```

# 19. Relación con CID

Una amenaza puede afectar a cualquiera de los tres principios fundamentales de la seguridad:

## C — Confidencialidad

La información solamente debe ser accesible por las personas autorizadas.

Ejemplo:

> Un atacante consigue leer una base de datos privada.

Se ha afectado la:

**CONFIDENCIALIDAD**

---

## I — Integridad

La información no debe ser modificada de forma no autorizada.

Ejemplo:

> Alguien modifica las notas almacenadas en un sistema.

Se ha afectado la:

**INTEGRIDAD**

---

## D — Disponibilidad

Los sistemas y datos deben estar disponibles cuando sean necesarios.

Ejemplo:

> Un servidor deja de funcionar y los usuarios no pueden utilizar el servicio.

Se ha afectado la:

**DISPONIBILIDAD**

# 28. Idea principal de la sesión

La seguridad comienza antes del ataque.

Debemos ser capaces de identificar:

```text
AMENAZAS
    +
VULNERABILIDADES
    ↓
     RIESGOS
    ↓
Medidas de seguridad
    ↓
Reducir la posibilidad
y el impacto de los incidentes
```

La pregunta que debemos aprender a hacer ante cualquier sistema es:

> **¿Qué puede dañarlo, qué debilidad podría aprovecharse y qué consecuencias tendría?**
